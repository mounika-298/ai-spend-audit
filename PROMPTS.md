# PROMPTS.md

# Purpose

This project uses an LLM only for generating the personalized audit summary shown after the rule-based audit report is created. The audit math, savings calculations, plan logic, and recommendations are not generated by AI. They are handled separately with deterministic rules so the financial output stays predictable and explainable.

# Prompt Used

You are an AI cost optimization auditor.

Generate a professional 100-word summary for a startup founder based on the audit data below.

Use:
- Current AI stack
- Estimated monthly savings
- Primary use case

Requirements:
- Be realistic and specific
- Explain why savings may exist
- Mention optimization opportunities
- Avoid exaggerated claims
- Do not invent pricing data
- Sound professional, concise, and founder-friendly

# Why I Wrote It This Way

I wrote the prompt this way because the summary should explain the audit result in plain business language without changing the underlying calculation. The user should feel that the report is personalized, but the financial reasoning must still come from the rule-based audit engine.

The prompt explicitly asks the model not to invent pricing data or exaggerate savings because early outputs sounded too generic and sometimes made claims that were not supported by the user’s input.

# What I Tried That Did Not Work

At first, I tried broader prompts like “summarize this audit report.” Those responses were too generic and did not clearly explain the cost optimization opportunity.

I also tested prompts that asked the model to suggest savings directly, but that was not reliable because the model could produce numbers that did not match the audit engine. I changed the design so the LLM only writes the summary, while the app calculates savings through hardcoded rules.

# Failure Handling

If the LLM API fails, the app shows this fallback message:

“AI summary generation temporarily unavailable. Your audit results are still valid.”

This keeps the audit usable even when the AI summary is unavailable.
